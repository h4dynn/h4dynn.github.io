Expand description

Service monolith

Structure which contains configuration & the execution handle of the service. This should follow a fixed lifetime depending on the service’s pattern (see up for standard services & ServiceBody for the backend implementation).

§Initialization

Services are sourced (try_source) in the kickit binary first. This is done so we can weed out any kind of bad configurations, seperating from actual service initialization errors.

After all the services have been sourced, the kickit binary starts each one-by-one (up).

Finally, the service handles returned by the start method are moved to the STANDARD_SERVICES oncelock. Here they remain untouched until shutdown, where the handles are accessed to kill the services with down.

§Example

use std::thread::park;

#[tokio::main]
async fn main()
{
  // `try_source` method attempts to access /usr/lib/kickit/service/hellod.toml
  let mut hello_world_daemon = Service::try_source("hellod").handle();

  // The `start` method causes some values to be moved, leaving us with only a handle
  let _ = hello_world_daemon.start().await.handle();

  // Now, the process runs as a seperate tokio task. The init blocks until shutdown.
  loop {
    park();
  }
}

Note: services can only be initialized in the kickit init binary

pub async fn up(self) -> Result<Option<Self>>

This method will take ownership of the service, and only return a handle to it if standard

§Standard lifetime
    1. All services defined in the target are initialized by initServices(..) (method calls try_source for each service),
    1. This method is called by the init system,
    1. The process is started from the service’s executable, and then the service is broken up into its logger and Supervisor,

  • 4a. The logger reads from the process’s stdout and stderr, relaying each entry (seperated by newlines) to the log file,

  • 4b. The supervisor watches the process, waiting for it to exit. If it ever exits, it will throw an init error if the service is not optional, or just a warning if not,

    1. What is left of the service is moved into STANDARD_SERVICES, where it will be accessed upon system shutdown to gracefully kill the service (down)
§Errors

  • Failed to start the service’s main process (see Service::up errors)

  • Failed to start the logger (watches stdin and stderr, see Service::logger)

  • Failed to start the process supervisor (see Service::supervisor)

Source

pub fn down(&self) -> Result<()>

Gracefully kill a service, in the init process this is only called once by power::poweroff

§Implementation

As only one thread can own the Child process at a time (owned by the supervisor, as defined in the lifetime specification), this method relies on using the process’s PID to kill the process (using nix::sys::signal).

§Errors

  • This function expects the service to be running already.

  • This function can only be ran on services with Standard pattern.

async fn up_inner(&mut self) -> Result<()>

The underlying method used by up, this does majority of the work in handling the service’s process execution, logger initialization & caching. The up method will start the supervisor & logger task if the service is standard, jobs which are not this function’s responsibility

  • Couldn’t spawn or start a process for the service
