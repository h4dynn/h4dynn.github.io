Poweroff the system gracefully, performing required operations in a routine order

§Routine

The tasks performed by this method, to ensure graceful shutdown, in order:

  1. The OnceLock POWER_OFF_READY is initialized to true. This value is checked by the service supervisor after a service is killed/downed. Setting it tells the supervisor that the service has been downed as part of the poweroff process, and as such to not throw an error,

  2. Each service in the global OnceLock STANDARD_SERVICES is downed,

  3. Each mount entry in /proc/mounts is unmounted (except for critical system pseudo filesystems, like proc, dev & sys),

  4. The Linux system call reboot is called, with the relevant mode, and the kernel handles the rest of the poweroff process.

§Non-init process

When kickit is not ran as the init process, the behavior of this method is very different:

  • First off, only mount entries from the /run/kickit directory are unmounted. This is because the other mount entries (most likely sourced from /etc/fstab) are handled by the actual init system, so we don’t want to touch them.

  • Secondly, the /run/kickit directory is deleted. This is not relevant when powering-off as the init, since the run temporary filesystem will be unmounted anyways.

  • And finally, the kickit process is exited (no poweroff; again, this is the actual init’s job & not ours).
